# Mixed Environment AI Development

This document defines a practical development path for AI builders working across Linux-first and mixed environments.

## Purpose
Support AI development that remains teachable, portable, and adaptable across different systems while preserving strong documentation and builder habits.

## Core Goals
- make development paths easier to teach
- support Linux-first workflows where possible
- support mixed environments without losing clarity
- keep repo-based learning consistent
- turn environment setup into reusable lessons

## Builder Practices
- document setup steps clearly
- keep workflows command-line friendly when practical
- separate environment-specific notes from core concepts
- keep templates modular
- record lessons learned from setup and debugging
- convert recurring setup work into reusable guides

## Suggested Learning Sequence
1. Learn repo navigation and markdown documentation
2. Learn basic command-line habits
3. Learn environment setup and dependency notes
4. Learn AI workflow design and experimentation
5. Learn how to turn experiments into reusable templates
6. Learn how to document and teach the process to others

## Mixed Environment Notes
Examples of mixed environments:
- Linux development plus mobile access
- local experiments plus cloud-based workflows
- repo-based learning plus operational automation
