# Builder Review Loops

This document defines repeatable review loops for builders working across the wider `lippytm` AI and computer science education ecosystem.

## Purpose
Help builders improve quality, security, clarity, and reuse by making review a normal part of learning and development.

## Core Review Loop
1. Build a small lesson, workflow, or experiment
2. Review what it was supposed to do
3. Review what actually happened
4. Identify risks, failures, and unclear areas
5. Improve documentation, structure, or implementation
6. Convert improvements into reusable patterns or checklists

## Review Areas

### 1. Technical Review
- correctness
- clarity
- maintainability
- debugging notes
- dependency awareness

### 2. Security Review
- secrets handling
- scope boundaries
- safer defaults
- production vs sandbox separation
- review checkpoints

### 3. Educational Review
- was the lesson understandable
- was the example reusable
- were assumptions explained
- were failure cases documented

### 4. Builder Growth Review
- what skill improved
- what remained confusing
- what should be practiced again
- what can become a reusable learning asset

## Best Practices
- review in small loops, not only at the end
- document lessons learned immediately
- treat failure cases as valuable training material
- connect review outcomes back to templates and kits
