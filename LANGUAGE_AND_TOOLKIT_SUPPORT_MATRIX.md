# Language and Toolkit Support Matrix

This document defines a broad support matrix for programming languages, machine learning tooling, blockchain development tools, and related builder ecosystems inside the wider `lippytm` education and development system.

## Purpose
Provide a flexible structure for supporting many languages, libraries, toolkits, and applied development paths without forcing every builder into one narrow stack.

## Core Principle
Support many tools, but teach builders how to choose and use them through clear purpose, documented patterns, and reusable learning systems.

## Support Categories

### 1. Core Programming Languages
Examples:
- Python
- JavaScript
- TypeScript
- SQL
- shell scripting
- optional systems languages as the ecosystem grows

Focus:
- where each language fits
- how they connect to shared concepts
- how to move between languages through applied practice

### 2. Computer Science Toolkits
Examples:
- data structures and algorithm practice tools
- debugging tools
- testing frameworks
- API and HTTP tooling
- documentation and repo tools

Focus:
- foundational builder habits
- repeatable development workflows
- reusable patterns across environments

### 3. Machine Learning and AI Toolkits
Examples:
- model APIs
- embeddings and retrieval tools
- workflow orchestration concepts
- evaluation patterns
- agent-support tooling

Focus:
- practical AI workflow design
- repeatable experimentation
- review and safety integration

### 4. Blockchain and Web3 Toolkits
Examples:
- wallet and account tooling
- smart contract development workflows
- testing and deployment patterns
- chain interaction tooling
- documentation and architecture notes

Focus:
- applied builder education
- reusable project structures
- safe experimentation and review habits

### 5. Environment and Setup Toolkits
Examples:
- Linux-first workflows
- mixed-environment development notes
- environment setup checklists
- credential and secret handling habits
- dependency documentation

Focus:
- portability
- reproducibility
- builder confidence across systems

### 6. Sandbox Support Toolkits
Examples:
- isolated lesson environments
- experimental workflow spaces
- agent testing contexts
- blockchain practice environments
- reflective review loops

Focus:
- safe experimentation
- clear boundaries
- reusable educational exercises

## Best Practices
- keep toolkit explanations tied to real use cases
- compare tools by purpose instead of hype
- connect toolkits back to shared builder habits
- include setup, review, and security notes in every toolkit path
- convert strong toolkit workflows into reusable learning kits
